# Checkout UI

KuluPay provides a **framework-agnostic checkout component** that handles the entire payment flow — wallet detection, connection, transaction submission, and on-chain confirmation polling — with a single mount call.

## Architecture

```
@kulupay/kulupay/checkout          ← headless core (vanilla TS)
  ├─ createCheckout()              ← state machine: load → connect → pay → poll
  ├─ mountCheckout()               ← renders the full UI into a container element
  └─ Wallet detection              ← MetaMask, Coinbase, Phantom, Trust, Rabby, Rainbow, OKX, TronLink

@kulupay/kulupay/checkout/react    ← thin React wrapper (~30 lines)
@kulupay/kulupay/checkout/vue      ← thin Vue wrapper (~35 lines, Nuxt compatible)
```

All payment logic lives in the headless core. Each framework binding is just a thin wrapper that mounts the core into a DOM element. Fixing a bug or adding a wallet updates every framework at once.

<Callout type="info">
  The checkout UI supports both **light** and **dark** themes. Pass `theme="light"` or `theme="dark"` to any binding.
</Callout>

## React (Next.js)

```tsx title="app/checkout/page.tsx"
"use client";

import { use, Suspense } from "react";
import { CheckoutPage } from "@kulupay/kulupay/checkout/react";
import { payClient } from "@/lib/pay-client";

function CheckoutContent({ searchParams }: { searchParams: Promise<{ intentId?: string; clientSecret?: string }> }) {
  const params = use(searchParams);

  if (!params.intentId || !params.clientSecret) {
    return <div>Missing parameters</div>;
  }

  return (
    <CheckoutPage
      intentId={params.intentId}
      clientSecret={params.clientSecret}
      client={payClient}
      merchantName="Acme Inc"
      theme="light"
    />
  );
}

export default function CheckoutRoute({ searchParams }: { searchParams: Promise<{ intentId?: string; clientSecret?: string }> }) {
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <CheckoutContent searchParams={searchParams} />
    </Suspense>
  );
}
```

### Props

| Prop | Type | Required | Description |
|------|------|----------|-------------|
| `intentId` | `string` | Yes | Payment intent ID from `createIntent` |
| `clientSecret` | `string` | Yes | Client secret from the intent response |
| `client` | `PayClientLike` | Yes | Pay client instance from `createPayClient()` |
| `merchantName` | `string` | No | Shown in the checkout header |
| `theme` | `"light" \| "dark"` | No | Default `"light"` |

## Vanilla JS (any framework)

For frameworks without a dedicated binding — Angular, SolidJS, Svelte, or plain HTML:

```ts title="checkout.ts"
import { mountCheckout } from "@kulupay/kulupay/checkout";
import { createPayClient } from "@kulupay/kulupay/client";

const client = createPayClient({ baseURL: "/api/pay" });

const handle = mountCheckout(document.getElementById("checkout")!, {
  intentId: "pi_12345",
  clientSecret: "pi_12345_secret_abc",
  client,
  merchantName: "Acme Inc",
  theme: "light",
});

// Clean up when done
handle.unmount();
```

<Callout type="info">
  `mountCheckout` returns a `CheckoutHandle` with a `controller` property (for programmatic access) and an `unmount()` method.
</Callout>

## Headless Usage

If you want to build your own UI entirely, use `createCheckout()` to get the state machine without any rendering:

```ts
import { createCheckout } from "@kulupay/kulupay/checkout";
import { createPayClient } from "@kulupay/kulupay/client";

const client = createPayClient({ baseURL: "/api/pay" });

const checkout = createCheckout({
  intentId: "pi_12345",
  clientSecret: "pi_12345_secret_abc",
  client,
  pollInterval: 5000,
});

// Subscribe to state changes
checkout.state.subscribe((state) => {
  console.log("Step:", state.step);
  console.log("Intent:", state.intent);
  console.log("Wallets:", state.wallets);
  console.log("Error:", state.error);
});

// Initialize — loads intent and detects wallets
await checkout.init();

// Programmatic control
await checkout.connect();    // connect to selected wallet
await checkout.pay();        // send payment transaction
checkout.destroy();          // stop polling and clean up
```

### CheckoutState

```ts
interface CheckoutState {
  step: "loading" | "error" | "select-wallet" | "connected"
      | "paying" | "pending-confirmation" | "succeeded"
      | "failed" | "expired" | "redirect";
  intent: CheckoutIntentData | null;
  wallets: WalletInfo[];
  selectedWallet: WalletInfo | null;
  address: string | null;
  txHash: string | null;
  error: string | null;
}
```

### Controller Methods

| Method | Description |
|--------|-------------|
| `init()` | Load the intent and detect available wallets |
| `selectWallet(id)` | Select a wallet from the detected list |
| `connect()` | Connect to the selected wallet |
| `pay()` | Send the payment transaction via the connected wallet |
| `redirect()` | For redirect providers (Stripe, Chapa, PayPal) — navigate to hosted page |
| `destroy()` | Stop polling and clean up resources |

## The Payment Flow

1. **Client** calls `createIntent` → receives `intentId` and `clientSecret`
2. **Client** navigates to checkout page with those params
3. **Checkout core** loads the intent via `checkoutIntent` API
4. **Checkout core** detects installed wallets in the browser
5. **User** selects a wallet and clicks "Launch extension"
6. **Checkout core** calls `connectWallet()` → wallet prompts user to connect
7. **User** clicks "Pay" → checkout core calls `sendPayment()` → wallet prompts transaction
8. **Checkout core** calls `confirmIntent` API with the tx hash
9. **Checkout core** polls `verifyIntent` every 5 seconds until status is `succeeded`/`failed`/`expired`
10. **UI** updates to show success/failure state

<Callout type="warn" title="Important">
  The checkout UI requires the intent to have a `checkoutFlow` of `"self-hosted"` for blockchain payments. Redirect providers (Stripe, Chapa, PayPal) use the `"redirect"` flow and show a "Continue with [Provider]" button instead.
</Callout>

## Custom Checkout (Self-Hosted)

If you want full control over the checkout UI — your own design, your own wallet connection, your own payment logic — you can build it entirely yourself using the KuluPay API.

### How It Works

1. **Client** calls `createIntent` → receives `intentId`, `clientSecret`, and `raw` transaction data
2. **Your code** renders whatever UI you want
3. **Your code** connects to the user's wallet (MetaMask, TronLink, WalletConnect, etc.)
4. **Your code** sends the transaction using the `raw` data from the intent
5. **Your code** calls `confirmIntent` with the transaction hash
6. **Your code** polls `verifyIntent` until the status is `succeeded` or `failed`

### Server Configuration: `checkoutUrl`

Set `checkoutUrl` on the server to give clients a ready-made redirect URL:

```ts title="lib/pay.ts"
import { kuluPay } from "@kulupay/kulupay";

export const pay = kuluPay({
  database: drizzleAdapter(db, { provider: "pg" }),
  // ... providers, plugins, etc.

  // When set, the createIntent response includes a `checkoutUrl` field
  // with intentId and clientSecret already embedded.
  checkoutUrl: "/checkout?intentId={intentId}&clientSecret={clientSecret}",
});
```

The `createIntent` response will include:

```json
{
  "id": "pi_abc123",
  "clientSecret": "pi_abc123_secret_xyz",
  "checkoutUrl": "/checkout?intentId=pi_abc123&clientSecret=pi_abc123_secret_xyz",
  "raw": {
    "to": "0x1c7d4b196cb0c5b537566c3ab4ddf2b53b3b3c7b",
    "value": "0",
    "data": "0xa9059cbb...",
    "chainId": 11155111,
    "tokenSymbol": "USDC",
    "isNative": false,
    "contractAddress": "0x1c7d4b196cb0c5b537566c3ab4ddf2b53b3b3c7b"
  }
}
```

### Client: Redirect After Intent Creation

```tsx title="app/page.tsx"
"use client";
import { payClient } from "@/lib/pay-client";
import { useRouter } from "next/navigation";

export default function Home() {
  const router = useRouter();

  const handlePay = async () => {
    const result = await payClient.createIntent({
      body: {
        amount: 1000,
        currency: "usd",
        providerId: "ethereum",
        token: "USDC",
      },
    });

    if (result?.data?.checkoutUrl) {
      // Server provided the URL — just redirect
      router.push(result.data.checkoutUrl);
    } else if (result?.data?.id && result?.data?.clientSecret) {
      // Fallback: build the URL yourself
      router.push(`/checkout?intentId=${result.data.id}&clientSecret=${result.data.clientSecret}`);
    }
  };

  return <button onClick={handlePay}>Pay $10.00</button>;
}
```

<Callout type="info">
  `checkoutUrl` is optional. If not configured on the server, the field is `undefined` and the client builds the URL manually from `id` and `clientSecret`.
</Callout>

### Building Your Own Checkout UI

Use the `checkoutIntent` API to load the full intent data, then build your own UI:

```tsx title="app/custom-checkout/page.tsx"
"use client";
import { useEffect, useState } from "react";
import { payClient } from "@/lib/pay-client";
import { useSearchParams } from "next/navigation";

export default function CustomCheckout() {
  const searchParams = useSearchParams();
  const intentId = searchParams.get("intentId")!;
  const clientSecret = searchParams.get("clientSecret")!;
  const [intent, setIntent] = useState<any>(null);
  const [txHash, setTxHash] = useState<string | null>(null);
  const [status, setStatus] = useState<string>("pending");

  // 1. Load the intent data
  useEffect(() => {
    payClient.checkoutIntent({
      query: { intentId, clientSecret },
    }).then((res) => setIntent(res.data));
  }, [intentId, clientSecret]);

  // 2. Send the transaction using your own wallet code
  const handlePay = async () => {
    const raw = intent.raw;
    // Use viem, ethers, tronweb, or any wallet library
    const hash = await window.ethereum.request({
      method: "eth_sendTransaction",
      params: [{
        to: raw.to,
        value: raw.value,
        data: raw.data,
      }],
    });
    setTxHash(hash);

    // 3. Confirm with the server
    await payClient.confirmIntent({
      body: { intentId, txHash: hash, clientSecret },
    });

    // 4. Poll for confirmation
    const poll = setInterval(async () => {
      const res = await payClient.verifyIntent({
        query: { intentId, clientSecret },
      });
      setStatus(res.data.status);
      if (res.data.status === "succeeded" || res.data.status === "failed") {
        clearInterval(poll);
      }
    }, 5000);
  };

  if (!intent) return <div>Loading...</div>;

  return (
    <div>
      <h1>Pay {intent.amount / 100} {intent.currency.toUpperCase()}</h1>
      <p>Token: {intent.raw.tokenSymbol}</p>
      <button onClick={handlePay} disabled={!!txHash}>
        {txHash ? "Confirming..." : "Pay Now"}
      </button>
      {txHash && <p>TX: {txHash}</p>}
      <p>Status: {status}</p>
    </div>
  );
}
```

### Key API Endpoints for Custom Checkout

| Endpoint | Method | Auth | Purpose |
|----------|--------|------|---------|
| `/create-intent` | POST | Session | Creates the payment intent, returns `raw` tx data |
| `/checkout-intent` | GET | clientSecret | Loads full intent data for checkout rendering |
| `/confirm-intent` | POST | clientSecret | Submits the tx hash after user sends the transaction |
| `/verify-intent` | GET | clientSecret | Polls for on-chain confirmation status |

<Callout type="warn" title="Important">
  When building a custom checkout, you are responsible for:
  - Wallet connection and network switching
  - Balance checks before sending transactions
  - Error handling for rejected transactions
  - Polling for confirmation status
  
  The built-in `CheckoutPage` component handles all of this automatically.
</Callout>
